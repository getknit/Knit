# ADR 2026-09.j8c7 — A photo-less avatar wears its node id's hue, in a fixed palette shared with the notification shade

Status: Accepted (2026-09-10) — closes the "node-id-derived avatar hue" follow-up ADR 058 left on the
roadmap.

**What was observed.** `ui/components/Avatar` drew every photo-less contact as the same
`secondaryContainer` disc with an initial, so a chat list of eight strangers was eight identical
grey-lavender circles and the initial was the only thing telling rows apart. The notification shade had
already solved this for itself: `MessageNotifier.letterAvatar` keyed an HSV hue on the identity (360
buckets, saturation 0.5, value 0.65, white letter), with a KDoc admitting "the in-app avatar is one fixed
tint and does not mirror this". So the same person was grey in the list and, say, teal in the shade, and
a second person with the same name (ADR 058's whole concern) was indistinguishable in the list until the
alias was read.

**What changed.** `Avatar` takes a `nodeId: String?` (no default — every call site says what the face
stands for) and colours the disc and the initial from one of **twelve `AvatarTint`s** chosen by
`avatarTintIndex(key) = floorMod(key.hashCode(), 12)`. The palette is generated by
`scripts/gen-avatar-palette.py` on the HCT port in `gen-color-scheme.py`: hues 30° apart; the disc at
tone 85 in light and tone 30 in dark; the initial at tone 10 / tone 90, the same container /
on-container pairing every `*Container` role in `Color.kt` uses. The chroma is **capped at what the
weakest hue can reach at that tone** (20 light, 28 dark), not requested per hue: HCT gamut-maps by
dropping chroma, and at tone 85 a coral holds ~21 while a green holds ~86, so asking every hue for the
same generous number makes the greens shout. The tables live in `KnitSemanticColors.avatarTints`, keyed on
dark mode like the pinned green and for the same reason: a colour that stands for *who* must not be handed
to the wallpaper, or Ada is green on one phone and violet on another (Material You gets a bounded nudge,
below, never the palette). `MessageNotifier.letterAvatar` now draws
from `AvatarTintsLight` through the same index, fixed to the light pair the way `roomAvatar` already was
(the shade's polarity is the system's, not the app's).

The key is the **node id**, never the display name, wherever there is one: it survives a rename, it is
the same on every phone that knows the peer (it is derived from the pinned public key), and a change of
colour means a change of key. For a DM the conversation id *is* the node id, so the chat list, the
request list and search pass that. The three places that used to force `primaryContainer` — your own
avatar on Settings and the profile editor, and a peer's on their profile page — now derive too, so the
colour you see yourself in is the one others see you in. The one face with no identity behind it is a
heard Meshtastic **stranger**: its key is the `!hex` node label (`MeshOrigin.nodeLabel`), because the row's
sender column is this phone by convention (ADR 2026-09.sre4) and keying on it would paint every stranger
in the owner's colour. A matched contact keys on `origin.peerId`.

The alternative a reader reaches for first is keeping the notifier's approach and lifting it in-app:
hue = hash mod 360 in HSV. Rejected because HSV lightness is not perceptual — at a fixed S/V a yellow
is far lighter than a blue, so the letter's contrast and the discs' visual weight vary by hue, which is
exactly the tacky look.

**Under Material You the palette is harmonized**, as Material's own guidance for custom colours says:
`KnitTheme` maps the mode's table through `AvatarTint.harmonizedToward(colorScheme.primary)` when the
wallpaper scheme is in force, and `MessageNotifier` does the same to the light pair with
`dynamicLightColorScheme(context).primary`, gated on the same `ThemePreferences.dynamicColor` flag, so
the list and the shade still agree. The rule is `Blend.harmonize`'s — turn the hue toward the accent by
half the difference, never more than 15°, lightness and chroma untouched — applied in **Oklch rather than
HCT**: the same rule, in a space with a closed-form inverse, so twenty-four colours re-derive at theme
time with no CAM16 solver in the app. A turned hue that leaves the sRGB gamut (a light saturated yellow
turned toward orange) is fitted by lowering chroma at fixed lightness, the way HCT gamut-maps, because
lightness is what carries the initial's contrast; clamping channels would have darkened it. A grey accent
(a monochrome wallpaper theme) turns nothing. The price is the one this ADR first deferred over: under
Material You the same person can differ by up to 15° between two phones with different wallpapers.
Bounded is the point — Ada stays a green, the wallpaper's kind — and under the coral scheme the tables
are still used verbatim, so the static case is byte-identical everywhere.

**What it costs, and what it does not cover.** No wire, DB or DataStore change; `ProfileHeader` gains a
`nodeId` field so the Settings row can key on it. Twelve buckets means two contacts in twelve share a
colour, so this is a cue, **not a fingerprint** — nothing should ever compare colours to decide identity;
the safety number does that. `String.hashCode()` is the Java-specified polynomial, stable across ART
versions and phones; the slot assignment is pinned by `ColorSchemeTest.avatarTintSlotIsStableAcrossPhonesAndVersions`
(a real-shaped node id, `Int.MIN_VALUE`'s string, the empty string) so a "better" hash or a resized
palette fails a test instead of recolouring everyone after an update. The trap for the next person is
the generator's constraint: **do not raise a chroma above the floor `check()` prints** — the script
refuses, and the reason is the paragraph above. `everyAvatarTintClearsTextContrast` holds the initial to
AA's 4.5:1 in both modes and `avatarTintsWalkTheWheelOnceAndAgreeAcrossModes` catches a hand-edited row
that swapped or drifted between the light and dark tables. The harmonize path has its own four:
`oklchRoundTripsWithinAStep`, `harmonizeTurnsTheHueTowardTheAccentByAtMostFifteenDegreesAndMovesNothingElse`
(compared as 8-bit colours against the rule's own turn, because at a pastel's chroma one quantisation step
is a degree of hue), `harmonizeTowardAGreyIsANoOp`, and `harmonizedAvatarTintsStillClearTextContrast`
across six wallpaper primaries.
